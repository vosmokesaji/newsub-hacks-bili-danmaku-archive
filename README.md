# NEW 字幕组《Hacks / 绝望写手》B 站弹幕归档

保存 NEW 字幕组 B 站投稿的弹幕，供日后配合 NAS 中的 NEW 字幕组五季原片播放。本仓库不包含视频。

**弹幕抓取已结束；NAS 原片时间轴校准尚未完成。** 当前 `merged/` 只能作为按 B 站切片顺序拼接的临时版本，尚未扣除相邻 P 的重叠，不能直接视为与 NAS 原片同步。

## 来源与抓取范围

- 投稿者：NEW 字幕组；作品：`Hacks / 绝望写手`。
- 已确认的原投稿入口：[S01E01 / BV1XWBXBcE3Q](https://www.bilibili.com/video/BV1XWBXBcE3Q/)、[S01E02 / BV1wpvkB3EGk](https://www.bilibili.com/video/BV1wpvkB3EGk/)。用户还提供了两者的 `p=6`、`p=4` 链接。
- 原投稿下架后，视频详情和分 P 查询接口返回 `-404`；公开搜索仍保留部分标题和 BV，但没有足够的 CID 数据。
- CID 来源：[Internet Archive 于 2026-09-09 14:40:54 UTC 保存的第一集页面](https://web.archive.org/web/20260909144054/https://www.bilibili.com/video/BV1XWBXBcE3Q/)。从该页面 `window.__INITIAL_STATE__` 内的合集元数据提取了 BV、CID、分 P 名称、顺序及整数秒时长。详见 [CID目录.json](hacks-danmaku/CID目录.json)。
- 下载日期：2026-10-28，北京时间。弹幕数据直接来自 B 站分段接口，不是从其他剧集弹幕库匹配而来。
- 实际使用的接口：`https://api.bilibili.com/x/v2/dm/web/seg.so`；补抓改用 `https://api.bilibili.com/x/v2/dm/wbi/web/seg.so`。参数包括 `type=1`、`oid=CID`、`pid=AV号`、`segment_index`；新版接口额外使用 WBI 签名。
- [分段接口说明](https://github.com/BACNext/bilibili-API-collect-backup/blob/master/docs/danmaku/danmaku_proto.md)、[WBI 签名说明](https://sessionhu.github.io/bilibili-API-collect/docs/misc/sign/wbi.html)为社区维护资料，不是 B 站官方稳定 API 承诺。

这里的“取得数据”是成功保存接口当时返回的弹幕池，并不代表从投稿至下架的全部历史弹幕；未登录接口也可能只返回部分内容。本次未使用登录账号、SESSDATA 或历史弹幕接口。

## 文件组织

```text
README.md                         来源、处理方法与限制
AGENTS.md                         后续修改与提交约定
Hacks_NEW_下载状态.md              本次抓取覆盖情况
docs/时间轴状态.md                  每集时长线索、占位 P、疑似删减清单
processing/timeline-status.json    同一份状态的结构化数据
scripts/audit_archive.py           本地校验并生成时间轴状态清单
hacks-danmaku/
  CID目录.json                    存档页面中的分 P 元数据
  分段下载结果.json                下载结果；file 相对此目录
  归档汇总.json                    归档和临时合并情况
  待补下载.json                    当前为空
  S01E01/ ... S05E10/             分 P 原始 XML 和 .segmentNN.pb
  S05_预告/                       预告的独立归档
  merged/                         37 份未经重叠校准的临时整集 XML
```

每个分 P 文件名保留原投稿页码、分 P 名称和 CID。原始 XML 中每条弹幕时间是**该分 P 内的相对秒数**，PB 中 `progress` 为毫秒。XML `p` 属性的第 8 项是弹幕 ID，第 9 项在部分文件中为权重；不能把最后一项一律当作弹幕 ID。

## 已经做过的处理

1. **找回 CID 并逐包归档。** 每个分 P 按 6 分钟分包下载；保存原始 protobuf 和可读取的 XML，按弹幕 ID 去重，保留文本、时间、模式、字号、颜色、发送时间等可用字段。
2. **处理旧接口关闭提示和风控。** 旧 XML 接口返回“本视频弹幕功能已被关闭”，不是有效弹幕；此前 215 个分 P 的旧分段请求返回 JSON `-352`。补抓改用新版 WBI 接口、正常匿名会话、完整 UA/Referer、约每 2 秒一次的串行请求和连续失败停止策略，215 个分 P 均成功恢复。未使用账号 Cookie，未将 JSON 错误响应当作 `.pb` 弹幕。
3. **保留完整性依据。** 下载阶段逐条对照 PB 与 XML 的文本、时间和 ID，验证 291 个分 P、369 个分包、29,782 条弹幕；另验证归档 ZIP 的 CRC 和清单路径。
4. **排除数字名占位 P 后临时合并。** `merged/` 只处理与该集匹配的 `SxxExx-*` 切片；不把名称为 `0`、`1` 或其他非标准长 P 串入正片。它们的原始文件仍独立保留，未删除弹幕。
5. **修正过一次约 40 分钟的偏移。** 更早版本曾把数字名占位 P 的 2417 秒计入整集时间轴；更新版已排除。基线提交使用的是这一更新版。

数字名占位 P 涉及 S02E02、S02E04、S04E01、S04E02、S04E04、S05E07、S05E09、S05E10。其中 S04E01 还包含末尾的数字名 `1`；S05E09 只有 `0`/`1` 两个非标准长 P，不能假定两者应首尾相接。

S05E08 只有一个非标准名称长 P，存档时长 4404 秒；S05E09 的两个 P 时长为 2417、4518 秒。它们没有生成 `merged/` 整集文件，需要单独核对内容及时间轴，不能仅凭长度判断属于动画或删减版。

## 尚未完成的时间轴校准

### 相邻 P 的重叠

用户确认相邻 P 存在数秒重叠；举例中的秒数不是实际测量值。当前合并算法仍是：

```text
临时整集时间 = 分 P 内弹幕时间 + 前面所有同集命名切片的存档时长之和
```

因此越往后的 P 越可能因未扣除重叠而逐渐偏移。**本仓库尚未按固定 2 秒/3 秒扣减，也没有把总时长差均摊到每个接点。**

精确校准需获取 NAS 原片的实际媒体时长，并为每个分 P 找到可比对的音频、画面或字幕锚点，确定其在原片中的起止位置。若分 P 内也发生剪辑，需建立多段映射，而不是只给整个 P 一个偏移值。

当前归档只有整数秒级分 P 时长及弹幕，没有视频、音轨、首帧或原片起止点。**单集总时长只能提供差值，不能唯一确定每个接点的重叠量或删减位置。** NAS 原视频的可访问路径尚待提供；在有证据前，状态均标为未校准。

### 疑似删减

以下 4 集存在原分 P 名称中的 `【删】` 标记，已单列为**名称线索提示的疑似删减，未实测**：

|剧集|原分 P 名称|CID|
|---|---|---:|
|S03E02|S03E02-2【删】|36999204497|
|S03E03|S03E03-2-2【删】|37047436123|
|S05E03|S05E03-5-2【删】|38035326571|
|S05E07|S05E07-1-1【删】|38860621025|

具体 CID 以 [时间轴状态](docs/时间轴状态.md) 和原始 [CID目录](hacks-danmaku/CID目录.json) 为准。没有 `【删】` 的集数同样可能有未标注的剪辑，不能据名称证明完整；也不能把“总时长较短”直接判定为删减，因为还可能有片头片尾、重复段、不同版本或取整误差。

校准时应记录：原片时长与识别依据、每个 P 的来源区间、每个重叠区间、删减区间、排除的占位 P、异常长 P 的处理决定。只有这些信息确定后再输出 NAS 播放版本。

## 本地校验与状态生成

需要 Python 3.9+ 标准库，无额外依赖、无需联网：

```bash
python3 scripts/audit_archive.py
git diff --check
```

脚本校验清单路径、XML 条数、弹幕 ID、原始分包与 XML 的文本/时间一致性，并更新 `docs/时间轴状态.md`、`processing/timeline-status.json`。它不会修改原始弹幕，也不会凭空校准时间轴。

后续每次完成变动必须提交。提交使用 Conventional Commits，例如 `fix(timeline): 校准第一集相邻切片重叠`；正文按需用中文记录依据、影响和验证。
